# JobFinder Database

## Engine

PostgreSQL is the primary database.

The backend uses **async SQLAlchemy 2.0** with the `asyncpg` driver.

## Connection

The database URL is configured through the environment and is **not
hard-coded**.

```text
DATABASE_URL=postgresql+asyncpg://<user>:<password>@<host>:<port>/<database>
```

This value lives in `backend/.env` (local, never committed) with placeholders
in `backend/.env.example`.

## SQLAlchemy Configuration

Engine and session factory: `backend/app/core/database.py`

- Async engine via `create_async_engine`
- `AsyncSession` produced through `async_sessionmaker`
- Pool size and max overflow are configurable via `DATABASE_POOL_SIZE` and
  `DATABASE_MAX_OVERFLOW`
- `pool_pre_ping=True`
- Sessions are created and closed through the `get_db` dependency

## Migrations

Database schema changes use Alembic.

Configuration: `backend/alembic.ini`, `backend/alembic/env.py`

The `Base.metadata` in `backend/app/core/database.py` is the source for
autogenerated migrations.

Currently there are **no migrations** and **no models** — the schema is
planned for the next phases.

## Planned Schema

The initial V1 schema is intentionally focused on:

```text
Users
Profiles
Companies
Jobs
Applications
SavedJobs
```

AI, messaging, and subscription-related tables are intentionally excluded from
V1.

### Planned Relationships

```text
User 1 ─── 1 Profile
User 1 ─── N Application
User 1 ─── N SavedJob
Company 1 ─── N Job
Job 1 ─── N Application
Job 1 ─── N SavedJob
```
